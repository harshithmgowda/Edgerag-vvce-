# 📋 Track 6: Shared Data Contracts & Schemas (`contracts/`)

**Assigned Responsibility**: Shared Architecture Contract  
**Tech Stack**: JSON Schema (Draft 7/2020-12), TypeScript Type Definitions  
**Git Scope**: `chore(contract): <description>` or `feat(contract): <description>`  

---

## 🎯 Domain & Purpose

The `contracts/` directory contains the source-of-truth data schemas that bridge the **Headquarters Backend**, **Web Portal**, and **Mobile Android App**. Any change here must be backward compatible to ensure air-gapped field devices never fail synchronization.

---

## 📁 Files & Schemas

```
contracts/
├── incident.schema.json              # Offline field incident schema (UUID, severity, notes, photos)
├── package-manifest.schema.json      # Knowledge package manifest schema (hashes, chunks, equipment)
├── examples/
│   ├── incident-payload-sample.json  # Sample sync payload from mobile
│   └── knowledge-manifest-sample.json# Sample package manifest generated by backend
└── README.md                         # This specification guide
```

---

## 🔒 Contract Rules for Team Members

1. **Immutable UUIDs**: Field incidents must generate cryptographically random UUIDv4 identifiers on device creation.
2. **Deterministic Manifests**: Package manifests must specify `sqlite_checksum_sha256` matching the exact SHA-256 hash of `knowledge.sqlite`.
3. **No Breaking Schema Changes Mid-Hackathon**: Always add optional fields rather than renaming existing required properties.
